Before TRIA / With TRIA

A system remembers that a person prefers meetings after 10 AM. Later, that person withdraws permission for persistent context. What happens when the agent tries to use the old preference again?
The relationship changes over time
T0 · Preference stored“I prefer meetings after 10 AM.”
T1 · Permission withdrawnThe person revokes persistent-context consent.
T2 · Agent actsThe assistant prepares to use the stored preference.
Without relational governance

Historical access can look like present authority.

Stored preference exists → preference is retrieved → agent uses it.

The system may still possess the information. Possession alone does not tell it whether using that information remains authorized now.

Outcome: the old preference may still influence the action.
With TRIA

Current relationship state governs consequence.

Stored preference exists → current consent is resolved → consent is revoked → use is blocked.

TRIA separates historical state from current authority. A prior grant is not silently treated as permanent permission.

Outcome: BLOCKED before consequence.
TRIA does not make the AI smarter. It changes what the system is permitted to treat as true, available, authorized, and actionable across time.

The difference is not memory. It is relationship state.

Both systems can retain historical information. The TRIA-governed system additionally represents consent and authority as state that can change, be revoked, and be resolved again before a consequential operation.

In the canonical SDK-backed Consent & Revocation scenario, execution succeeds while the required consent and READ permission are active. After revocation, a subsequent attempt is evaluated against current state and does not execute.
