# Clean-room remediation specification decisions

Baseline: 0.1.0a3 at 463ce26b8af7d52d38796888cf5717948df1e331, 116 original tests pass, frozen verdict NOT YET. Original audit artifacts outside this repository remain untouched. `tests/frozen/clean_room_witnesses.py` is a byte-identical copy of the five audit assertions, explicitly rerun before editing implementation.

## Normative choices, recorded before implementation

1. Execution authority is resolved again after all adapter/resource preparation. A supported store guard serializes final authorization, invocation-start recording and synchronous executor invocation with SDK writes. Final evaluation is bound to the original InvocationRequest, not a cached plan or custom Runtime's assertion of ALLOW. Changes during reentrant evaluation must be detected and fail closed. This is a local invocation linearization guarantee, not cancellation or atomic commit of a remote effect. The trusted executor owns effects after entry, remote idempotency, retries and transport. A revocation that acquires the guard first wins; one arriving after executor entry cannot undo an already-started effect. Expiry is sampled at the final authorization decision, not guaranteed throughout an external operation.
2. Host administrative access is a capability of possessing the Relationship/Tria Python object. Introduce explicitly named `rel.admin` permission administration. Keep documented legacy grant/revoke aliases to avoid silently breaking existing hosts, with identical participant validation. Strings are attribution, not authentication. Do not expose these host objects or `tria:system` bootstrap operations to agents. Participant requests must name registered participants. Missing/empty relationships cannot authorize. Invalid histories remain inspectable through audit but cannot operate.
3. Causal ambiguity is a derived projection property shared by GovernanceEngine and Relationship, not an aggregate-only check. Caller-created empty state fails closed. A trusted host can still fabricate Python objects; this library is not a hostile-host sandbox. Projection changes require a version boundary and old portable projections must be rejected rather than silently reinterpreted.
4. Stores reject stale predecessors atomically. Concurrent attempts may return an explicit conflict; no automatic blind retry. File-backed SQLite supports atomic append transactions and a process ownership guard for supported SDK use. Cross-process access to the same live database fails clearly; direct SQL/host mutations are outside the library trust boundary. The exact frozen scheduled writer witness may now raise a documented conflict instead of reaching its original final assertion. Preserve that witness unchanged and test safe rejection separately.
5. Final blocked authority produces a nonexecution receipt and auditable resolution. Executor failures after entry are UNKNOWN_EFFECT unless the executor explicitly reports a known failure. No response is never silently completed. New request IDs identify new attempts; retry ownership remains with the host, and the same invocation ID must not execute twice in one persisted relationship.
6. External data is resolved by a host callable only after declared checks; no silent None for unknown resources. Resolvers/adapters are trusted extensions, cannot supply authentic identity or infer purpose, and may not weaken final declared requirements.
